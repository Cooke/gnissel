## Project Overview

Gnissel is a micro ORM for .NET that provides a lightweight alternative to Entity Framework and Dapper. It targets .NET 9.0 and uses Roslyn source generators for zero-allocation object mapping.

**Key characteristics:**
- Thread-safe DbContext (can be used as singleton)
- No change tracking or navigation properties
- Async enumerable interface throughout
- PostgreSQL-only currently (via Cooke.Gnissel.Npgsql adapter)
- Compile-time code generation via source generators

## Architecture

### Project Structure

The solution contains three main production projects and their test counterparts:

1. **Cooke.Gnissel** - Core database-agnostic ORM
   - `DbContext`: Main entry point for raw SQL queries
   - `Typed/` namespace: LINQ-style type-safe queries via `Table<T>`
   - `Sql` class: Interpolated string handler for safe SQL parameterization
   - All abstractions: `IDbAdapter`, `IMapperProvider`, `IObjectReaderProvider`, etc.

2. **Cooke.Gnissel.Npgsql** - PostgreSQL adapter implementation
   - `NpgsqlDbAdapter`: Implements `IDbAdapter` for PostgreSQL
   - `NpgsqlDbAdapter.TypedQueryProcessing.cs`: Expression-to-SQL translation for typed queries
   - `NpgsqlDbAdapter.Formatting.cs`: SQL rendering with PostgreSQL parameter syntax (`$1`, `$2`, etc.)

3. **Cooke.Gnissel.SourceGeneration** - Roslyn incremental source generator
   - `Generator.cs`: Main generator entry point
   - Discovers types needing mapping via `[DbMappers]` attribute or automatic detection
   - Generates `ObjectReader<T>` and `ObjectWriter<T>` implementations at compile time

### Core Abstraction Layers

**DbContext Flow:**
```
User Code
  → DbContext.Query<T>(sql)
  → DbOptions.GetReader<T>() (from generated code)
  → ObjectReader<T> (generated by source generator)
  → DbConnector.ExecuteQuery()
  → IDbAdapter.RenderSql()
  → Database
```

**Typed Query Flow:**
```
Table<User>.Where(x => x.Name == "Bob")
  → TypedQuery<User> (immutable query builder)
  → ExpressionQuery (holds LINQ expression tree)
  → IDbAdapter.GenerateTypedQuery() (expression → SQL translation)
  → Query<User> (regular query execution)
```

### Key Components

**Sql Interpolated String Handler**
- Location: `src/Cooke.Gnissel/Sql.cs`
- Converts `$"SELECT * FROM users WHERE id={userId}"` into parameterized SQL
- Fragment types: `Literal`, `Parameter<T>`, `Identifier`, `Raw`
- Use `Sql.Inject()` for explicit SQL injection (table/column names from user input)

**ObjectReader<T> and ObjectWriter<T>**
- Location: `src/Cooke.Gnissel/ObjectReader.cs`, `ObjectWriter.cs`
- Generated by source generator, not written manually
- Uses descriptors (`ReadDescriptor`, `WriteDescriptor`) for column mapping
- Supports constructor parameters, init properties, nullable types, nested objects

**ExpressionQuery (Typed Queries)**
- Location: `src/Cooke.Gnissel/Typed/Queries/ExpressionQuery.cs`
- Immutable record holding query state (table, selector, joins, conditions, groupings, orderings, limit)
- Built via `with` expressions in `TypedQuery<T>` methods
- Converted to SQL by adapter's expression visitor

**Name Providers**
- `DefaultDbNameProvider`: No transformation
- `SnakeCaseDbNameProvider`: Converts PascalCase → snake_case
- Affects table names, column names, nested properties
- Set via `DbOptions`

### Source Generation

**How to Use:**
In test/application code, define:
```csharp
[DbMappers]
private partial class Mappers;
```

The generator will:
1. Scan for `Table<T>` properties, `.Query<T>()` calls, `[DbMap]` attributes
2. Generate reader/writer methods for all discovered types
3. Fill in `Mappers` class with `ReaderProvider`, `WriterProvider`, `NameProvider`

**Reader Generation Logic:**
- Selects longest constructor
- Matches constructor parameters to database columns
- Handles init-only properties, required properties
- Null handling: returns null if all fields are null (for nullable types)
- Supports enums (as string, as int, or original value)

**Important Files:**
- `Generator.DbReaders.Pipelines.cs`: Type discovery logic
- `Generator.DbReaders.Reader.Method.cs`: Reader method generation
- `Generator.DbWriters.Writer.Method.cs`: Writer method generation

### Test Architecture

**Test Infrastructure:**
- Uses **Testcontainers** to spin up real PostgreSQL containers
- `Fixture.cs` in each test project creates container in `[SetUpFixture]`
- Tests run against actual PostgreSQL, not mocks

**Test Pattern:**
```csharp
[TestFixture]
public class MyTests
{
    [DbMappers] private partial class Mappers;  // Source generator fills this in

    private class TestDbContext(DbOptions options) : DbContext(options)
    {
        public Table<User> Users { get; } = new(options);
    }

    private TestDbContext _db = null!;

    [OneTimeSetUp]
    public async Task Setup()
    {
        _db = new TestDbContext(/* ... */);
        await _db.NonQuery($"CREATE TABLE users(...)").ExecuteAsync();
    }

    [TearDown]
    public async Task TearDown()
    {
        await _db.NonQuery($"TRUNCATE users").ExecuteAsync();
    }
}
```

**Test Frameworks:**
- Cooke.Gnissel.Test: **NUnit**
- Cooke.Gnissel.Typed.Test: **XUnit**
- Cooke.Gnissel.SourceGeneration.Test: Verify snapshot testing

## Important Patterns

### Async Enumerable Everywhere
All queries return `IAsyncEnumerable<T>`:
```csharp
await foreach (var user in dbContext.Query<User>($"SELECT * FROM users"))
{
    // Process user
}

// Or materialize:
var users = await dbContext.Query<User>($"SELECT * FROM users").ToArrayAsync();
```

### Immutable Query Building
Typed queries use immutable records with `with` expressions:
```csharp
var query = dbContext.Users
    .Where(x => x.Age > 18)      // Returns new TypedQuery<User>
    .OrderBy(x => x.Name);       // Returns new TypedQuery<User>
```

### Parameter vs Literal vs Injection
```csharp
var userId = 1;
var tableName = "users";

// Parameter (safe, preferred):
$"SELECT * FROM users WHERE id={userId}"

// Identifier (escaped):
$"SELECT * FROM {Sql.Identifier(tableName)}"

// Injection (dangerous, use carefully):
$"SELECT * FROM {Sql.Inject(tableName)}"
```

### Multi-Type Query Results
```csharp
var results = await dbContext.Query<(User user, Device? device)>(
    $"SELECT u.*, d.* FROM users u LEFT JOIN devices d ON u.id=d.user_id"
).ToArrayAsync();

// If all device columns are null, device will be null
```

### Custom DbContext with Tables
```csharp
public class AppDbContext(DbOptions options) : DbContext(options)
{
    public Table<User> Users { get; } = new(options);
    public Table<Device> Devices { get; } = new(options);
}

// Usage:
var users = await dbContext.Users.Where(x => x.Name == "Bob").ToArrayAsync();
```

## Working with Source Generators

When modifying the source generator:

1. **Debug Setup**: Set `Cooke.Gnissel.SourceGeneration.Test` as startup project
2. **Viewing Generated Code**: Build the project, then check `obj/` folders or use IDE navigation
3. **Testing Changes**: Run `Cooke.Gnissel.SourceGeneration.Test` which uses snapshot testing
4. **Key Classes**:
   - `Generator.cs`: Main pipeline setup
   - `Generator.DbReaders.Pipelines.cs`: Discovers types needing readers
   - `Generator.DbReaders.Reader.Method.cs`: Generates reader methods
   - `ParameterMatching.cs`: Matches constructor parameters to columns

## Expression to SQL Translation

Located in `NpgsqlDbAdapter.TypedQueryProcessing.cs`:

**Supported LINQ Operations:**
- `Where()`, `Select()`, `OrderBy()`, `ThenBy()`
- `Join()`, `LeftJoin()`, `RightJoin()`, `FullJoin()`, `CrossJoin()`
- `GroupBy()` with `Db.Count()`, `Db.Sum()`, `Db.Avg()`, `Db.Min()`, `Db.Max()`
- `First()`, `FirstOrDefault()` (uses LIMIT 1)

**Expression Translation:**
- Binary operators: `==`, `!=`, `>`, `<`, `>=`, `<=`, `&&`, `||`
- Member access: Translates to column references
- Constants: Become parameters
- Method calls: `Db.*()` aggregates, string methods (StartsWith, Contains, etc.)
- Anonymous types: Projected in SELECT

**Adding New Expression Support:**
1. Update `RenderExpression()` in `NpgsqlDbAdapter.TypedQueryProcessing.cs`
2. Add corresponding test in `Cooke.Gnissel.Typed.Test`
3. Handle both expression rendering and parameter extraction

## Common Gotchas

1. **Source Generator Not Running**:
   - Clean and rebuild: `dotnet clean && dotnet build`
   - Check project reference includes: `ReferenceOutputAssembly="false" OutputItemType="Analyzer"`

2. **Tests Failing to Connect**:
   - Ensure Docker is running (Testcontainers needs it)
   - Check `Fixture.cs` setup is called (should be automatic with `[SetUpFixture]`)

3. **Enum Mapping**:
   - By default, enums are stored as integers
   - Use `[DbMappers(EnumMappingTechnique = MappingTechnique.AsString)]` for string storage
   - Can be configured per-type with `[DbMap]` attribute

4. **Null Handling in Multi-Type Queries**:
   - Mark type as nullable (`Device?`) for LEFT JOIN results
   - If all columns are null, the entire object becomes null

5. **Name Mapping**:
   - Default is exact match (PascalCase properties → PascalCase columns)
   - Use `SnakeCaseDbNameProvider` for C# PascalCase → SQL snake_case
